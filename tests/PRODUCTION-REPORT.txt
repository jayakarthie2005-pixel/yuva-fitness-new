  SECTION 1: ARCHITECTURE AUDIT (PHASE 1)
=====================================================================

Stack:
  Frontend  Static HTML/CSS/JS (no framework, no build step)
            index.html (2092 lines) — home, contact, about, equipment modals
            franchise/gallery.html (1314 lines) — franchise form + gallery
            CSS: custom properties, mobile-first, no CSS framework
            JS: vanilla, Google ReCAPTCHA-style, zero external libs

  Backend   Two Vercel serverless functions (Node.js + node-fetch 2.x):
            /api/send-enquiry.js       — gym membership enquiry (261 lines)
            /api/send-franchise-enquiry.js — franchise enquiry (224 lines)
            Both run in 10s timeout window, fully independent.

  Database  NONE (stateless serverless)

  Auth      NONE

  Deploy    Vercel (CDN + serverless, auto-scales)

  Secrets   5 env vars required:
            TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID
            WHATSAPP_ACCESS_TOKEN, WHATSAPP_PHONE_NUMBER_ID,
            WHATSAPP_RECIPIENT_NUMBER

Rate Limiting (per handler, identical logic):
  In-memory Map, sliding window, 5 requests per IP per 60s
  Auto-cleanup when map exceeds 20,000 entries
  Frontend UI guard: submit button disabled after first click (separate)

Outbound:  Telegram Bot API + WhatsApp Business (Meta Graph API)
  AbortController timeout: 10 seconds per outbound call
  Both sent in parallel via Promise.allSettled()
  200 = both delivered | 207 = partial | 502 = neither delivered

Security Headers (vercel.json):
  HSTS, nosniff, DENY frame, strict referrer, restrict camera/mic/geo

Honeypot:
  Hidden 'website' field — if filled, pretends success (200 OK),
  does no work, no outbound calls.

Validation:
  400 with errors[] array on any invalid field.
  Sends only accepted enums for budget/space/property/timeline/goal.
